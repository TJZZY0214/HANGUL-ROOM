```
①資料蒐集 → ②資料擷取與 ingest → ③內容檢查 → ④建立 Wiki → ⑤查詢 Wiki
    ↑              ↑   │                │            │            │
    └──────────────┘   └────────────────┘            │            ▼
                  ③ 不通過返回 ②                      │        ⑥整理教學摘要
                                                    │            │
```

## 3. 重複執行的條件（Loop）
| 迴圈 | 觸發條件 | 結束條件 |
|---|---|---|
| ③→②→③ | 檢查發現數字不符、來源衝突、擷取失敗或被限流 | 資料通過檢查，或明確標為待補來源 |
| ⑦→④→⑤→⑥→⑦ | 驗證發現句子無來源，或 Wiki 資料不足 | 所有句子可追溯，且無待補內容 |
| ⑦→⑥→⑦ | 摘要措辭與 Wiki 不一致 | 一致 |
| ⑨→⑧→⑨ | 任一功能測試失敗 | 全部測試通過，或失敗項目已記錄且使用者同意延後 |
| ⑩→⑨ | 公開網址無法開啟或功能異常 | 公開網址實測通過 |

## 4. 避免 AI 產生無來源教學內容的機制
1. **單一知識來源**：簡報只能從 Wiki 取材，不得使用 AI 記憶。
2. **逐句標註**：Wiki 每項事實都有 `[S#]`；教學設計與推論另行標示。
3. **待補標記**：資料不足時寫 `【待補來源】`，⑦ 會阻擋這些內容進入簡報。
4. **狀態誠實**：ingest 只能記錄實際讀到的範圍；工具摘要必須標明。
5. **反向驗證**：⑦ 由簡報句子反查 Wiki 與來源，找不到就退回。
6. **逐字查證**：單字逐一查詞典；不寫沒有來源的例句。
7. **獨立檢查**：高風險內容（史實、發音規則）由未參與撰寫的檢查者覆核。
8. **使用者核對**：`human_check` 在使用者實際核對前保持 `pending`。

## 5. 執行紀錄的保存
- 逐步紀錄：`logs/run-YYYYMMDD.md`。
- 測試結果：`workflow/test-report.md`。
- 來源紀錄：`sources/sources.json`。
- 網站流程展示頁：由上列檔案產生，內容必須一致（第三階段實作）。
- 失敗與修正：照實保留。沒有失敗就記錄成功，不製造錯誤。
